# くろぬりんDesktop

Web版「くろぬりん」と同じ操作感で、**PDFの分割・結合・ファイル名の一括変更・電子署名**を行うダウンロード型デスクトップアプリ（Electron製）です。

ファイルは一切外部に送信しません。PDFの処理も署名も、すべて手元のPC内で完結します（アプリは外部通信を行いません）。

---

## できること

| 機能 | 内容 |
| --- | --- |
| 分割 | ページ範囲指定（`1-3,5,8-`）／Nページごと／1枚ずつ／選択ページのみ抽出。ファイル名テンプレート付き |
| 結合 | 複数PDFをドラッグで並べ替えて結合。ファイルごとにページ範囲を絞り込み可 |
| ページ編集 | サムネイルを選んで回転・削除（保存するまで元ファイルは変更しません） |
| リネーム | 検索置換（正規表現可）＋テンプレート（`{base}` `{n}` `{yyyy}{mm}{dd}` など）で一括変更。実行前にプレビュー、実行後は1クリックで元に戻せます |
| 電子署名 | PKCS#12（`.p12` / `.pfx`）の電子証明書でPDFにデジタル署名。印影・手書きサイン画像の貼り付けにも対応 |
| 署名の検証 | 署名後に文書が改変されていないか、署名者は誰かを表示 |
| 提出前の点検 | フォント埋め込み・パスワード保護・注釈・添付ファイル・JavaScript・ページサイズ・メタデータ・署名をまとめてチェック |
| メタデータ削除 | 作成者・作成ソフトなどの情報を落として出力（相手方に渡す書面向け） |
| 既定のPDFアプリ | インストーラーが `.pdf` を関連付け。OSの設定画面から既定アプリに指定できます |

## 提出前の点検（プリフライトチェック）

「点検」タブでPDFを開いて **「この文書を点検」** を押すと、差し戻しの原因になりやすい点を一覧で確認できます。
**ファイルは一切書き換えません。**

| 点検項目 | 判定 | よくある原因 |
| --- | --- | --- |
| フォントの埋め込み | 未埋め込みがあれば**要修正** | Word→PDF変換でフォントを埋め込んでいない。相手方の環境で字体が変わる・文字化けする |
| パスワード保護 | 暗号化されていれば**要修正** | 保護をかけたまま提出しようとしている |
| 電子署名 | 検証できなければ**要修正**／署名があれば情報表示 | 署名後に分割・回転をして署名が壊れている |
| 注釈・フォーム | 残っていれば**要確認** | 校正時の付箋・ハイライトの消し忘れ |
| 添付ファイル | あれば**要確認** | 別ファイルが埋め込まれたまま |
| JavaScript・自動処理 | あれば**要確認** | 元ファイルに残っていたスクリプト |
| ページサイズ | 混在していれば**要確認** | A4とA3が混ざっている（用紙名と寸法を表示） |
| メタデータ | 残っていれば**要確認** | 作成者名・事務所名・作成ソフトが相手方に見える |

判定はいずれも一般的な注意点です。**提出先ごとの要件（署名形式・用紙・様式）は各提出先の案内で確認してください。**

## 開発時の動かし方

```bash
cd desktop
npm install          # pdf.js / pdf-lib は postinstall で src/renderer/vendor/ に配置されます
npm start            # アプリを起動
npm run dev          # 開発者ツールを開いた状態で起動
npm test             # 分割・結合・リネーム・署名・点検のロジックをテスト（41件）
npm run smoke        # 実際にウィンドウを起動して「開く→分割→回転→結合→署名」を通しで実行
```

`npm run smoke` はLinuxでは `xvfb-run` を使います。macOS / Windows では
`npx electron test/smoke.js` で実行してください。結果と画面キャプチャは `.smoke/` に出ます。
なお `@pdf-lib/fontkit` はテストで埋め込みフォント入りのPDFを作るためだけに使う開発用の依存です。

## 配布用にビルドする

```bash
npm run dist:mac     # .dmg / .zip（arm64・x64）
npm run dist:win     # NSISインストーラー（.exe）
npm run dist:linux   # AppImage / deb
```

ビルドは**そのOS上で行う必要があります**（macOS版はMacで、Windows版はWindowsで）。

### コード署名について（配布する場合の実務ポイント）

| OS | 必要なもの | 署名しない場合 |
| --- | --- | --- |
| macOS | Apple Developer Program（年間 99 USD）＋ 公証（notarization） | 「開発元を検証できません」となり、右クリック→開くの手順が必要 |
| Windows | コード署名証明書（OV / EV、年額数万円） | SmartScreenが「WindowsによってPCが保護されました」を表示 |

自分の事務所内だけで使うなら署名なしでも問題ありません（初回だけ警告を回避する操作が要ります）。
第三者に配布する、あるいは事務所の信用に関わる形で配る場合は署名を推奨します。

## 既定のPDFアプリにする

インストーラーが `.pdf` の関連付けを登録するので、あとはOS側で「既定」に切り替えます。
アプリのヘッダーにある「既定のPDFアプリにする」ボタンから案内が出ます。

- **Windows**: 設定 →「既定のアプリ」→ `.pdf` →「くろぬりんDesktop」を選択（ボタンから設定画面を直接開きます）
- **macOS**: Finderで任意のPDFを右クリック →「情報を見る」→「このアプリケーションで開く」で選択 →「すべてを変更...」
- **Linux**: `xdg-mime default kuronurin-desktop.desktop application/pdf`

関連付けから開かれたPDFは、起動時（macOSは `open-file` イベント、Windows / Linuxは起動引数）に自動で読み込まれます。

> 既定のPDFアプリにすると「PDFを開く＝このアプリが開く」ことになります。閲覧が主目的の場合は、
> 既定はAcrobatやプレビューのままにして、本アプリは「右クリック →このアプリで開く」で使う運用が快適です。

## 電子署名についての重要な注意

このアプリが付与するのは **PAdES-B-B 相当（PKCS#7 detached, `adbe.pkcs7.detached`）** の電子署名です。
Adobe Acrobat Readerで開けば「署名済み」と表示され、署名後の改変も検出できます。

一方で、次の点は**このアプリの対象外**です。実務で使う前に必ず確認してください。

1. **タイムスタンプ（PAdES-B-T）・長期署名（B-LT / B-LTA）は付きません。**
   認定タイムスタンプ（TSA）が必要な手続には使えません。
2. **登記・供託オンライン申請システムに提出する添付書面**は、法務省が動作確認している署名方法・
   ソフトが前提です。自作アプリで署名したPDFが受理される保証はありませんので、
   登記申請の添付書面については従来どおり法務省の対応ソフトを使ってください。
   本アプリは、**事務所内の稟議・相手方への提示・契約書の当事者署名**など、
   受付側がソフトを限定しない場面での利用を想定しています。
3. **ICカード（マイナンバーカード・司法書士電子証明書）には現時点で未対応**です。
   秘密鍵をファイルとして取り出せる PKCS#12（`.p12` / `.pfx`）形式のみ対応しています。
   ICカード対応にはPKCS#11（OpenSC等）経由の署名実装が必要で、将来の拡張余地として設計を分けてあります
   （署名処理は `src/main/sign.js` に閉じています）。
4. **検証は簡易検証です。** 「署名後に文書が変わっていないか」「署名者の証明書は誰か」までを確認しますが、
   認証局の失効確認（CRL / OCSP）やトラストアンカーの検証は行いません。

また、**署名は必ず最後の工程**にしてください。署名後に分割・回転・削除を行うと署名は無効になります。

## ファイル構成

```
desktop/
├── src/
│   ├── main/
│   │   ├── index.js      メインプロセス（ウィンドウ・メニュー・IPC・ファイル関連付け）
│   │   ├── preload.js    画面に公開するAPI（contextBridge）
│   │   ├── rename.js     リネームの計画作成と実行（2段階リネームで入れ替えにも対応）
│   │   ├── sign.js       PKCS#12署名・証明書情報・署名検証
│   │   └── preflight.js  提出前の点検（フォント埋め込み・注釈・メタデータ等）
│   ├── shared/
│   │   └── pdf-ops.js    ページ範囲の解釈・分割・結合・回転・削除・印影貼付（Node/画面 共用）
│   └── renderer/
│       ├── index.html    画面
│       ├── style.css     Web版くろぬりんと同じ配色
│       ├── app.js        画面のロジック
│       └── vendor/       pdf.js・pdf-lib（npm installで自動配置。Gitには含めません）
├── test/                 ロジックのテストと起動スモークテスト
├── electron-builder.yml  配布ビルドの設定（ファイル関連付けを含む）
└── build/                署名用のentitlements
```

### 設計方針

- **ファイルに触る処理はメインプロセスだけ。** 画面側は `contextIsolation: true` / `nodeIntegration: false` で、
  `preload.js` が公開したAPIしか呼べません。
- **PDFの中身の操作は共有モジュール（`src/shared/pdf-ops.js`）に集約**し、Nodeのテストからも画面からも
  同じコードを呼びます。ページ指定の解釈やファイル名の安全化はここでテスト済みです。
- **リネームは「計画」と「実行」を分離**しています。重複・既存ファイルとの衝突は実行前に検出され、
  該当行は実行されません。実行は一時名を経由する2段階なので、A→B・B→Aの入れ替えも安全です。
